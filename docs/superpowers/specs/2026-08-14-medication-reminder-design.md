# 开源安卓吃药提醒应用设计

## 1. 产品定位

这是一个面向老人及普通长期用药者的开源安卓应用。第一版只解决三件事：按计划可靠提醒、确认服用后留下记录、根据计划与库存估算还能服用多久。

应用采用 GPL-3.0 许可证。第一版完全离线，不注册账号、不连接服务器，也不申请网络权限。它只负责记录与提醒，不推荐剂量、不判断药物相互作用，也不提供诊断或治疗建议。

### 目标

- 用户清除最近任务后，已安排的提醒仍能由安卓系统触发。
- 锁屏时尽可能显示全屏闹钟式提醒；权限不允许时明确降级并告知用户。
- 只有用户确认“已服用”才扣减库存。
- 库存预计不足 7 天时，每天提醒补药。
- 界面适合老人：字大、对比强、点击区域大、信息层级少。
- 功能范围受控，以低缺陷率和可测试性优先。

## 2. 第一版范围

### 包含

- Android 8.0（API 26）及以上。
- 药品名称、计量单位、当前库存、单次用量和用药备注。
- 常见单位：片、粒、包、毫升、滴、喷、支，以及自定义单位。
- 每天一个或多个固定时间。
- 指定星期的一个或多个固定时间。
- 每 N 天在固定时间服用。
- 疗程开始日期和可选结束日期。
- 全屏服药提醒、确认已服用、10 分钟后提醒、跳过。
- 服药历史、补充库存和手动库存更正记录。
- 预计用完日期及剩余 7 天每日补药提醒。
- 通知、精确闹钟和全屏提醒权限状态检查。
- 本地备份导出与导入。

### 暂不包含

- 每 N 小时滚动服用。
- 按需服药的复杂统计或自动提醒。
- 家属共享、云同步、账号和 iPhone 客户端。
- 药品数据库、扫码、图片识别、剂量换算和药物相互作用。
- 医疗建议、复杂图表、广告和分析追踪。

这些能力只能在第一版稳定后单独设计和实现，不能以隐藏开关方式混入第一版。

## 3. 用户界面

应用使用 Jetpack Compose。视觉采用暖白背景、深绿色主色和琥珀色库存警告；不使用渐变、装饰插画或无意义动画。

底部只有四个入口：今日、药箱、记录、设置。

### 首页

首页采用已确认的“药箱卡片”方案：

1. 顶部显示日期和“我的药箱”。
2. 第一张卡片固定显示下一次服药时间、药名、剂量和“确认已服用”。
3. 下方按紧急程度显示药品库存卡片。每张卡同时显示剩余数量和预计还能使用的天数。
4. 预计不足 7 天的药品使用琥珀色左边线，并显示文字警告；颜色不是唯一提示。
5. 页面底部提供“添加药品”。

### 老年友好约束

- 常规正文不低于 16sp，药名不低于 20sp，关键时间约 30sp。
- 主要按钮高度至少 56dp，卡片整块可点击。
- 支持系统字体放大至 200%，不遮挡核心操作。
- 所有图标同时具有文字或无障碍描述。
- TalkBack 阅读顺序与视觉顺序一致。
- 破坏性操作需要清晰确认；常用操作不使用隐藏手势。

### 新增药品流程

新增流程分三步，避免一个页面堆积过多字段：

1. 药品：名称、单位、库存和备注。
2. 计划：单次用量、计划类型、时间、开始日期和结束日期。
3. 确认：用自然语言复述计划和预计库存结果，用户确认后才创建提醒。

编辑药品或计划时使用相同流程。保存成功后立即取消旧闹钟并安排新闹钟。

## 4. 提醒行为

### 系统实现

- 使用 `AlarmManager` 和基于 `PendingIntent` 的广播接收器，不依赖应用进程常驻。
- 精确服药提醒使用允许待机唤醒的精确闹钟；不使用不精确的重复闹钟累积误差。
- 每个计划只安排下一次事件。事件触发后立即计算并安排下一次，减少系统闹钟数量。
- “每 N 天”以用户选择的开始日期为锚点；固定时间计划遵循手机当前本地时间。夏令时跳过某个本地时刻时使用当天第一个可用时刻，时刻重复时只触发一次。
- 手机重启、时区改变、系统时间改变或应用升级后，从数据库重新建立所有待处理提醒。
- 同一分钟有多种药时合并为一个提醒页面，但每种药必须分别确认，避免一次点击错误扣减全部库存。

### 弹窗与重提醒

- 锁屏时，在系统允许且用户授权后唤亮屏幕并显示全屏提醒。
- 手机解锁且正在使用时，安卓可以显示展开式顶部通知，而不是强制覆盖当前操作。
- 全屏页面显示药名、剂量、计划时间，以及“已服用”“10 分钟后提醒”“跳过”。
- 页面不自动关闭；屏幕仍遵循系统自动熄屏时间，应用不阻止 Home 键或系统导航。
- 离开全屏页面后，通知继续保留。系统允许用户清除通知时，应用不尝试绕过系统控制。
- 初次提醒后若未处理，在 10、20、30 分钟各重新提醒一次，共三次重提醒。
- 最后一次重提醒结束 10 分钟后仍无操作，记录状态改为“未确认”，停止声音和振动，但保留可处理的通知。
- 如果全屏页面此时仍在前台，页面继续显示并切换为“未确认”状态；用户仍可处理或使用系统导航离开。
- 用户之后仍可将“未确认”更正为“已服用”或“已跳过”；若改为已服用，使用实际确认时间扣减库存。

首页允许提前确认下一次服药。计划时间尚未到时，确认框必须同时显示计划时间和当前时间；确认后记录为提前服用并取消该次提醒，避免按原时间再次弹窗。

默认使用系统闹钟声音并振动，单次响铃最多 60 秒。设置页允许分别关闭声音或振动，但不提供复杂铃声编辑器。

### 权限与降级

应用按需请求以下能力：

- Android 13 及以上的通知权限。
- Android 12 及以上的“闹钟和提醒”特殊访问。
- Android 14 及以上的全屏提醒特殊访问。
- 接收开机完成事件，用于恢复提醒。

应用必须在请求前用简短文字说明用途。全屏权限不可用时降级为锁屏大通知和顶部通知；精确闹钟权限不可用时使用不精确提醒，并在首页持续显示“提醒时间可能延迟”的警告。不能把降级伪装成正常状态。

在系统设置中“强制停止”应用后，安卓会取消提醒并阻止应用自行恢复。应用再次启动时重新安排提醒并告知用户。普通清除最近任务不应影响基于 `PendingIntent` 的系统闹钟。

参考：

- [Android AlarmManager](https://developer.android.com/develop/background-work/services/alarms)
- [Android 全屏紧急通知](https://developer.android.com/develop/ui/compose/notifications/create-notification#urgent-message)
- [Android 14 全屏提醒限制](https://developer.android.com/about/versions/14/behavior-changes-14#secure-fsi)

## 5. 数据与状态

### 主要数据

- `Medication`：药品名称、单位、当前库存、备注和启用状态。
- `Schedule`：药品、计划类型、时间或星期规则、间隔天数、开始/结束日期和单次用量。
- `DoseEvent`：计划时间、当前状态、实际处理时间和重提醒次数。
- `StockTransaction`：补充、消耗或更正的数量、时间、原因和关联服药事件。

服药事件状态固定为：待服用、稍后提醒、已服用、已跳过、未确认。

数量不能使用二进制浮点数保存。内部使用千分之一单位的整数表示数量，以支持半片和毫升小数，同时避免累计扣减误差。

### 状态规则

- “已服用”操作以单个数据库事务完成：更新事件状态、写入实际处理时间、写入库存消耗记录并更新当前库存。
- 重复点击同一个通知动作必须幂等，不能重复扣库存。
- “稍后提醒”“已跳过”和“未确认”不扣库存。
- 库存更正不能直接覆盖历史；必须产生一条更正记录。
- 删除仍有历史的药品时改为停用，不物理删除历史记录。

## 6. 库存预测与补药提醒

库存预测根据当前库存和未来有效计划逐次模拟消耗，直到库存不足或疗程结束。

- 如果库存会在有效疗程内不足，显示预计用完日期和剩余天数。
- 如果疗程先结束，显示疗程结束后的预计剩余量，不发送补药提醒。
- 没有有效计划时只显示库存数量，不猜测使用天数。
- 预计剩余 7 天或更少时，每天 09:00 发送一次普通补药通知。
- 用户可在设置中修改补药提醒时间，但阈值第一版固定为 7 天。
- 补充库存、停用药品或调整计划后立即重新计算；预计超过 7 天后取消每日补药提醒。
- 库存为零或已无法满足下一次计划时，通知使用“库存不足”文字，不只改变颜色。

补药提醒不使用全屏弹窗，不唤亮屏幕，也不重复响铃；只有服药时间提醒使用高优先级弹窗。

## 7. 架构

应用采用单安卓模块内的分层结构，避免第一版过度模块化：

- Compose 界面只负责展示状态和发送用户操作。
- ViewModel 组织页面状态，不直接访问 Room 或系统闹钟。
- 用例层封装确认服用、修改计划、补充库存、计算预测和导入导出。
- Repository 接口隔离本地数据来源，为未来云同步保留边界，但第一版只有 Room 实现。
- `AlarmCoordinator` 统一安排、取消和恢复系统闹钟。
- Room 保存业务数据；DataStore 保存声音、振动和补药提醒时间等简单设置。

关键规则如计划计算、库存预测和状态转换写成不依赖 Android UI 的纯 Kotlin 代码，并注入时间来源，以便确定性测试。

## 8. 隐私与备份

- 第一版不声明 `INTERNET` 权限，不含广告、分析、崩溃上传或第三方账号 SDK。
- 数据保存在安卓应用沙箱内，卸载应用会删除本地数据。
- 用户通过系统文件选择器主动导出 JSON 备份；导出前明确提示文件含有敏感用药信息。
- 导入先完整校验格式和版本，再在单个事务中写入；失败时不得留下半份数据。
- 导入不会覆盖现有数据。第一版采用“恢复为新数据库”的明确流程，用户确认后才替换，并在替换前生成临时回滚副本。
- 备份格式包含版本号，为后续迁移保留兼容入口。

## 9. 错误处理

- 权限被撤销：取消无法保证的精确行为，显示状态警告并提供系统设置入口。
- 数据库或备份校验失败：保留原数据，显示可理解的错误，不继续部分操作。
- 系统闹钟重复送达：按事件 ID 幂等处理。
- 时间或时区变化：重新计算未来事件，不改写已经确认的历史时间。
- 下一个计划时间已经过去：不立即制造多个过期弹窗；生成一条“未确认”记录后安排下一个未来事件。
- 库存出现负数：允许记录真实的“已服用”操作，但显示库存数据需要更正，不能静默截断为零。

## 10. 测试与验收

### 自动测试

- 计划计算：每日、多时间、指定星期、每 N 天、开始/结束边界、跨月和闰年。
- 时间变化：时区切换和夏令时重叠/跳过时刻。
- 库存：半片、小数单位、多计划共同消耗、疗程先结束、7 天阈值变化。
- 状态机：确认、跳过、稍后、未确认及后续更正。
- 幂等性：通知动作重复发送不重复扣库存。
- Room 事务、数据迁移和备份导入回滚。
- 重启与权限变化后的闹钟重建逻辑。

### 设备验收

- 至少覆盖 Android 8、12、13、14 和当前最新稳定版本的模拟器或实体设备。
- 从最近任务划掉应用后，锁屏提醒仍能触发。
- 重启手机后提醒能重建。
- 通知、精确闹钟或全屏权限拒绝时，应用显示正确降级状态。
- 全屏提醒三次重响的时间与状态正确。
- 系统字体放大 200% 和 TalkBack 下，核心流程可完成且无控件遮挡。
- 同一分钟多个药品不会相互覆盖或重复扣减。
- 强制停止后的不可恢复行为有明确说明，重新打开后能恢复计划。

### 第一版完成标准

只有以下条件全部满足，第一版才算完成：

1. 所有范围内的自动测试通过。
2. 关键设备验收场景通过并有记录。
3. 没有会导致漏提醒、重复扣库存、数据丢失或无法退出弹窗的已知高严重度缺陷。
4. README 清楚说明安装方式、权限、强制停止限制、隐私边界和非医疗建议声明。
5. 仓库包含 GPL-3.0 许可证、可重复构建说明和贡献指南。

## 11. 后续路线

稳定版之后依次评估：每 N 小时计划、按需服药记录、加密云同步、家属共享和 iPhone 客户端。每项都需要独立设计、迁移方案和测试范围，不与第一版并行开发。
